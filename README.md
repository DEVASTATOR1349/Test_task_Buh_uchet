# Отчёт по оплате работ на дату

Маленький HTTP-сервис на Python. Он читает выгрузку из `data/` и строит отчёт на дату:
по каждой работе — цена, выплачено и сколько осталось оплатить; по каждому договору — итоги.
Внешних зависимостей нет, только стандартная библиотека. Тот же сервис отдаёт веб-интерфейс
на React: он уже собран и лежит в пакете, поэтому Node для запуска не нужен.

- Задание — [TASK.md](TASK.md), формат данных — [data/FORMAT.md](data/FORMAT.md).
- Принятые решения и допущения — [DECISIONS.md](DECISIONS.md).
- Записка бухгалтеру — [NOTE_TO_ACCOUNTANT.md](NOTE_TO_ACCOUNTANT.md).
- Транскрипт работы с Claude Code — папка [transcripts/](transcripts/).

## Запуск

Нужен Python 3.9 или новее (проверено на 3.11, 3.12 и 3.14). Ставить ничего не нужно.

```bash
python -m advance_report            # из корня репозитория; слушает http://127.0.0.1:8000
```

Интерфейс: <http://127.0.0.1:8000/?date=2026-11-10>. Дату можно менять в шапке,
стрелками — по одному дню, так видно, как меняется отчёт до и после событий.

Тот же отчёт без интерфейса:

```bash
curl "http://127.0.0.1:8000/report?date=2026-11-10&format=text"   # таблица для чтения
curl "http://127.0.0.1:8000/report?date=2026-11-10"               # JSON
```

В Windows PowerShell вызывайте `curl.exe`, а не `curl`.

Параметры запуска: `--port 8000`, `--host 127.0.0.1`, `--data ПАПКА` (по умолчанию `data/`
рядом с кодом). CSV перечитываются на каждый запрос. Если в данных ошибка, сервис не
стартует и перечисляет все ошибки.

Тесты:

```bash
python -m unittest
```

### Веб-интерфейс (только чтобы его менять)

Исходники — в `web/` (React 19, TypeScript, Vite). Нужен Node 22.18 или новее.

```bash
cd web
npm install
npm run dev     # http://127.0.0.1:5173, запросы /report проксируются на запущенный сервис :8000
npm test        # тесты форматирования денег и дат (node --test)
npm run build   # проверка типов и сборка в advance_report/static/
```

Сборка лежит в git, чтобы проверяющим хватало Python. После правок в `web/` её нужно
пересобрать и закоммитить вместе с исходниками.

## API

`GET /report?date=ГГГГ-ММ-ДД[&format=json|text]` — отчёт. `GET /` — веб-интерфейс
(или краткая справка, если интерфейс не собран).

| Ответ | Когда |
|---|---|
| `200` | отчёт (`application/json` или `text/plain`, UTF-8) |
| `400` | нет даты, дата не в формате `ГГГГ-ММ-ДД`, неизвестный `format` |
| `404` | неизвестный адрес |
| `500` | ошибки в CSV — отчёт не строится, в `problems` указаны файл, строка и причина |

Суммы в JSON — строки с двумя знаками (`"185000.00"`), чтобы не потерять точность.
Статусы — коды из выгрузки, но пересчитанные на дату отчёта.

```text
report_date
contracts[]
  contract_id, contractor, signed_at, amount        договор
  works[]                                           работы
    work_id, title, status, status_date             статус на дату и дата приёмки/отмены
    price, paid, remaining                          цена, выплачено, осталось
    paid_from[] {payment_id, amount}                какими платежами оплачена
  totals
    works_due          стоимость неотменённых работ
    accepted           из них принятых
    paid               выплачено на дату (без возвращённых и без очереди)
    paid_to_works      зачтено в работы
    advance_unapplied  аванс, ещё не зачтённый в работы
    overpaid           переплата сверх стоимости всех работ
    remaining          осталось оплатить по договору = works_due − paid, не меньше 0
    accepted_debt      из них долг за уже принятые работы
    queued             в очереди на оплату (не выплачено)
  unapplied_from[]     из каких платежей сложились аванс и переплата
  payments[]           платежи на дату со статусом на эту дату
  warnings[]           что проверить человеку
totals                 те же поля, что у договора, — сумма по всем договорам
```

## Как считается

1. Статусы работ и платежей восстанавливаются на конец дня отчёта по датам событий.
2. Выплачено — деньги ушли не позже даты и к этой дате не возвращены. Очередь выплатой не считается.
3. Платёж с привязкой к работе идёт в свою работу. Если он больше цены работы, излишек уходит в общий котёл договора.
4. Котёл (платежи без привязки, в порядке оплаты) закрывает принятые работы, начиная с принятой раньше всех.
5. Остаток котла — аванс по договору. Если денег больше, чем стоят все неотменённые работы, разница — переплата.

Зачёт идёт целыми суммами, без делений, поэтому копейки сходятся без округлений.

## Устройство

```text
advance_report/
  money.py     разбор и вывод сумм и дат (Decimal, без float)
  data.py      чтение CSV и проверка целостности
  report.py    состояние на дату и зачёт платежей
  render.py    JSON и текстовая таблица
  server.py    HTTP (http.server): API и статика интерфейса
  __main__.py  запуск
  static/      собранный интерфейс (результат npm run build)
tests/         unittest: данные, расчёт, HTTP
web/           исходники интерфейса
  src/money.ts           деньги в копейках (BigInt) и даты; тесты — money.test.ts
  src/api.ts             типы ответа /report и запрос
  src/components/        сводка, договор (полоса оплаты, работы, итоги, платежи), состояния
  src/styles.css         токены цвета, светлая и тёмная тема, адаптация под телефон
```

Интерфейс ничего не пересчитывает: все суммы приходят с сервера. Сам он считает только
ширину сегментов полосы оплаты и сумму «ещё не оплачено и не в очереди» (остаток минус очередь),
причём в копейках, без float.

## Что не сделано и что дальше

- Ответы бухгалтера на вопросы из записки. Каждый из них меняет один параметр расчёта (см. DECISIONS.md).
- Выгрузка отчёта в CSV или XLSX для Excel — бухгалтеру так удобнее.
- Учёт допсоглашений (изменение суммы договора) и даты выгрузки — их нет в данных.
- Если бухгалтер выберет другой порядок зачёта, сделать его параметром.
